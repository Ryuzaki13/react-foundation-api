# Durable delivery через `@ryuzaki13/react-foundation-api/error-report`

Модуль доставляет versioned payload из IndexedDB queue `@ryuzaki13/react-foundation-lib/error-report`. Он владеет lease processing, timeout, retry/terminal policy и browser lifecycle, но не знает endpoint, auth и DB contract приложения.

```text
foundation-lib/error-report          foundation-api/error-report          app adapter/backend
capture + sanitize + IndexedDB ─────► lease + retry coordinator ─────────► serverFn / HTTP
```

## Установка и импорт

```bash
npm install @ryuzaki13/react-foundation-api \
  @ryuzaki13/react-foundation-lib
```

```ts
import { captureRuntimeErrorReport, createErrorReportQueue } from "@ryuzaki13/react-foundation-lib/error-report";
import {
	createErrorReportDeliveryCoordinator,
	ErrorReportDeliveryHttpError,
	type ErrorReportDeliveryAdapter
} from "@ryuzaki13/react-foundation-api/error-report";
```

## Быстрый старт

```ts
const queue = createErrorReportQueue();
if (!queue) {
	// IndexedDB недоступен: app фиксирует bounded fallback без рекурсивного report.
	return () => undefined;
}

const adapter: ErrorReportDeliveryAdapter = async (body, { signal }) => {
	const response = await fetch("/api/error-reports", {
		method: "POST",
		headers: { "Content-Type": "application/json" },
		body: JSON.stringify(body),
		signal
	});

	if (!response.ok) {
		const retryAfterSeconds = Number(response.headers.get("Retry-After"));
		throw new ErrorReportDeliveryHttpError(response.status, Number.isFinite(retryAfterSeconds) ? retryAfterSeconds * 1_000 : undefined);
	}
};

const coordinator = createErrorReportDeliveryCoordinator({ queue, adapter });
const stop = coordinator.start();

const draft = await captureRuntimeErrorReport(error, context, queryClient);
if (draft) {
	await coordinator.enqueue(draft.payload);
}
```

`coordinator.enqueue` будит delivery в текущей вкладке. Другие вкладки обнаружат запись через bounded poll; correctness не зависит от `BroadcastChannel`.

## Delivery body

`createErrorReportDeliveryBody(payload)` повторно runtime-валидирует payload и возвращает:

```ts
type ErrorReportDeliveryBody = {
	payloadVersion: number;
	application: string;
	buildId?: string;
	reportId: string;
	sessionId: string;
	createdUtc: string;
	category: ErrorReportCategory;
	errorClass: string;
	errorMessage: string;
	stackTrace?: string;
	payload: string;
};
```

`application`, `buildId` и `payloadVersion` дублируются с JSON для bounded DB columns и поиска. `payload` уже является JSON string; при сериализации внешнего HTTP body его не нужно stringify-ить отдельно второй раз.

Пустой `error.message` получает fallback `Неизвестная ошибка` одновременно в `errorMessage` и сериализованном payload. Future/unversioned payload отклоняется до adapter-а.

## Retry и terminal policy

| Failure                                                | Результат        |
| ------------------------------------------------------ | ---------------- |
| network `TypeError`, timeout/abort, неизвестная ошибка | retry            |
| HTTP `408`, `425`, `429`                               | retry            |
| HTTP `5xx`                                             | retry            |
| остальные HTTP `4xx`                                   | terminal discard |

Для status-aware результата adapter бросает `ErrorReportDeliveryHttpError(status, retryAfterMs?)`. Произвольный server response body и текст exception не сохраняются в IndexedDB.

Retry использует exponential backoff:

- база 5 секунд;
- multiplicative jitter `0.5–1.5`;
- максимум 15 минут;
- `Retry-After` может увеличить задержку, но тоже ограничен 15 минутами.

Неизвестная transport-ошибка считается retryable: временный сбой не должен необратимо уничтожить отчёт. Невалидный запрос server должен отвечать `4xx`, чтобы запись была удалена как terminal.

## Lease, timeout и idempotency

Coordinator по умолчанию использует:

- lease 30 секунд;
- timeout одной отправки 20 секунд;
- последовательный batch максимум 10 записей;
- fallback poll 30 секунд.

Timeout обязан быть меньше lease. При закрытии/crash вкладки запись снова доступна после истечения lease. `acknowledge`, `reschedule` и `discard` выполняются только владельцем текущего lease.

Backend обязан быть идемпотентным по `reportId`. Если server сохранил отчёт, а network acknowledgement или IndexedDB delete потерялись, queue отправит тот же ID повторно. Успешный duplicate request должен считаться server success, а не terminal conflict.

## Browser lifecycle

`start()` устанавливает только client-side listeners:

- немедленный flush при старте;
- `online` и `pageshow` ускоряют следующую попытку;
- возврат вкладки в visible state ускоряет попытку;
- bounded timer гарантирует progress без browser events.

`navigator.onLine` не используется как запрет отправки: браузер может ошибочно сообщать offline/online. Единственный владелец конкретной попытки определяется IndexedDB lease.

На SSR `start()` возвращает no-op cleanup и не устанавливает timer. При размонтировании/HMR нужно вызвать возвращённый `stop`; активный fetch получает abort signal.

## Coordinator events и storage failures

Optional `onEvent` получает только bounded технические события:

- `delivered`;
- `retry-scheduled`;
- `discarded` с optional HTTP status;
- `lease-lost` и стадия перехода;
- `storage-failure` и стадия операции.

Raw error, response text и payload в события не входят. Исключение самого observer подавляется, чтобы observability не создавала рекурсивный error report.

`coordinator.enqueue` преобразует IndexedDB quota/open/write failure в `{ status: "storage-error" }`. Background `flush` не выбрасывает storage failure наружу, а увеличивает `storageFailures` в результате. После успешной server delivery и неуспешного local acknowledgement запись остаётся под lease и позже повторяется с тем же `reportId`.

## Тестирование adapter-а приложения

Обязательно проверить:

- успешный ответ и server duplicate acknowledgement;
- HTTP `400/401/403/422` как terminal;
- HTTP `408/425/429/5xx` как retryable;
- передачу `AbortSignal` в фактический fetch/serverFn transport;
- потерю acknowledgement после server insert;
- отсутствие report recursion при ошибке endpoint;
- отсутствие raw response body в queue/events/logs.

Package tests дополнительно покрывают crash recovery, two-tab lease race, TTL, capacity, reopen, offline/online signal и quota failure.

## Полный API

| Export                                 | Назначение                                               |
| -------------------------------------- | -------------------------------------------------------- |
| `createErrorReportDeliveryBody`        | Строит validated server body из payload                  |
| `createErrorReportDeliveryCoordinator` | Управляет browser lifecycle, lease processing и delivery |
| `classifyErrorReportDeliveryFailure`   | Единая retry/terminal policy                             |
| `calculateErrorReportRetryDelay`       | Exponential backoff с jitter и cap                       |
| `ErrorReportDeliveryHttpError`         | Status-aware ошибка app adapter-а                        |
| `ErrorReportDeliveryTimeoutError`      | Технический timeout одной попытки                        |
| `ErrorReportDeliveryAdapter`           | Узкий contract transport-а приложения                    |
| `ErrorReportDeliveryCoordinatorEvent`  | Bounded observable lifecycle events                      |
